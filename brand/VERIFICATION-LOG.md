**도출된 규칙 — 이후 네이밍의 전제로 삼는다**

1. 짧고 발음하기 좋은 로마자 이름의 **`.com`은 예외 없이 전멸**이다.
   5개 후보 전부 `.com` 선점. 이는 우연이 아니라 시장 상태다.
2. `.net` 역시 선점되는 경향이 있다(2/2 확인).
3. **`.app`은 살아 있는 경우가 많다** — 5개 중 4개 가용, 전부 $9.99.
4. `.co`는 확인한 3개 전부 가용, $4.99로 가장 싸다.
5. `.io`는 가용성은 있으나 $37.99로 `.app`의 약 4배다.

**한계 — 반드시 인지할 것**
- Vercel 도메인 API는 **`.kr`을 취급하지 않는다.** 요청한 `baromi.kr`은 응답에서 누락됐다.
  국내 도메인은 이 경로로 확인 불가이며, 별도 등록대행(가비아·후이즈 등)에서 확인해야 한다.
- "available: false"는 **판매 불가**를 뜻하며, 등록자가 누구인지·언제 등록했는지는 알려주지 않는다.

### 3.2 「펜타로」 — 한국어 구조적 결함

**수단:** 네이버 블로그 검색
**결과:** "펜타로" 정확 일치가 사실상 없다. 검색엔진이 「펜타」로 범위를 넓혀 잡는다.

실제로 발견된 "펜타로" 용례는 **전부 조사 결합형**이었다:
- "콰트로치즈를 넘어 **펜타로**~" (버거킹 리뷰)
- "쿼드쎄라 **펜타로** 결정!!" (미용기기 리뷰)

**판정:** 한국어에서 `펜타로`는 명사로 파싱되지 않는다.
`펜타`(명사) + `로`(조사)로 읽힌다. 즉 브랜드명이 아니라
"펜타라는 것으로/펜타에게"라는 문장 조각으로 읽힌다.
이는 TENSEON이 "텐선"으로 읽혀 탈락한 것과 **같은 종류의 구조적 실패**다.

**부가 리스크:** 「펜타」는 현재 **버거킹 펜타치즈와퍼**(2026년 7월 출시)로
블로그가 포화 상태다. 「펜타」 블로그 검색 총 **327,523건**.
**탈락.**

### 3.3 이로부터 확립한 네이밍 규칙

> **한국어 조사 충돌 검사를 네이밍의 필수 관문으로 삼는다.**
>
> 이름의 끝음절이 한국어 조사(`로 · 와 · 과 · 에 · 의 · 도 · 만 · 나 · 까지 · 부터`)와
> 겹치면 브랜드명이 문장 조각으로 읽힌다.
> 모든 후보는 `OOO가` / `OOO를` / `OOO에서` 를 실제로 발음해 보고 통과해야 한다.

이 규칙은 실측에서 도출됐으므로 취향이 아니다.

## 6. 브랜드 핵심 자산의 정합성 — 코드 실측

크리틱 세션이 "확인하지 못했다"고 명시한 항목을 직접 조회했다. 결과는 아래와 같다.

### 6.1 비교 화면의 세그먼트 가드 — **부재 확인**

**규칙 문서가 규정하는 것** (`docs/specs/five-axis-scoring-rubric-ko.md`)

> 47행: **"공개 점수는 반드시 같은 세그먼트 안에서 계산한다."**
> 121행: "`5/5`: **같은 세그먼트에서** 깊은 볼을 만들기 쉬운 성향이 매우 강함"

즉 축 점수는 절대값이 아니라 **세그먼트 상대값**이다. 세그먼트는 무게
(`light_beginner` 260~285g / `balanced_mid` 286~300g / `performance` 301~315g /
`tour` 316g+)와 헤드사이즈(`98_class` / `100_class` / `oversize_class`)로 나뉜다.

**코드의 실제 상태**

```
$ grep -cni "segment" src/app/compare/page.tsx
0
```

- `src` 전체에는 `segment` 참조가 **178건** 있다. 즉 세그먼트 개념 자체는 살아 있다.
- `src/app/rackets/[slug]/page.tsx:50` 에는 `SEGMENT_LABELS` 가 있고 상세 화면에서 노출한다.
- 그러나 **`src/app/compare/page.tsx` 에는 `segment` 가 단 한 번도 등장하지 않는다.**

**귀결 — 확정된 결함**

비교 화면은 서로 다른 세그먼트의 라켓을 나란히 놓고 축 점수를 같은 표에 표시한다.
270g `light_beginner` 라켓의 「파워 4」와 320g `tour` 라켓의 「파워 4」가
**같은 숫자, 같은 막대, 같은 레이더 폴리곤**으로 그려지며, 화면 어디에도
"이 둘은 다른 기준으로 계산됐다"는 표시가 없다.

이것은 취향 문제가 아니라 **자체 규칙 문서를 화면이 위반하고 있는 상태**다.
그리고 이 제품의 브랜드 핵심 자산이 바로 그 5축 점수다.

### 6.2 총점 `N/15` 표기 — 확인

`src/lib/score-display.ts:147-154`

```ts
export function formatPublicTotal(scores: PublicAxisScores5): string {
  const total = Math.round(clamp(
    sumPublicAxisScores(scores),
    PUBLIC_TOTAL_MIN,
    PUBLIC_TOTAL_MAX,
  ));
  return `${total}/15`;
}
```

공개 총점의 하한은 10이다(`PUBLIC_TOTAL_MIN`). 따라서 **어떤 라켓도 10점 미만이 되지 않는다.**
그런데 화면 표기는 `13/15` 형태의 **분수**다. 분모가 있는 표기는 백분율 해석을 유발한다
(`13/15` → "87점"). 실제 변별 구간은 10~15의 **6단계**뿐이고, 사용자가 읽는 방식
(67%~100%)과 설계 의도(세그먼트 내 상대 배치)가 어긋나 있다.

`src/app/compare/page.tsx:96` 에서 이 값이 라켓 카드마다 「총점 N/15」로 노출된다.

### 6.3 브랜드 문자열 분기 — 확인

**이름을 바꿔도 규칙이 없으면 3종이 4종이 될 뿐이다.**

### 6.4 브랜드명이 하드코딩된 지점 — 확인

```
src/lib/admin-auth.ts:20:    .update("racketlab-admin-session:v1")
src/lib/compare.ts:5:const STORAGE_KEY = "racketlab_compare";
src/lib/wishlist.ts:14:const STORAGE_KEY = "racketlab_wishlist";
```

- `racketlab_wishlist` / `racketlab_compare` 는 **브라우저 localStorage 키**다.
  개명하면서 이 키를 함께 바꾸면 **기존 사용자의 위시리스트와 비교함이 조용히 사라진다.**
  마이그레이션 코드(구 키 읽기 → 신 키 쓰기 → 구 키 삭제) 없이는 데이터 손실이 확정적이다.
- `racketlab-admin-session:v1` 은 **세션 해시 salt** 다. 바꾸면 모든 관리자 세션이 즉시 무효화된다.

**권고:** 개명 시 스토리지 키는 **바꾸지 않는 것을 기본값**으로 한다.
키는 사용자에게 보이지 않는 내부 식별자이며, 브랜드 일관성을 위해 데이터를 잃을 이유가 없다.

### 6.5 커스텀 도메인 연결 여부 — **미연결 확인**

**수단:** Vercel API `get_project`
**프로젝트:** `racketlab` (`prj_wPzKAFzr9oLIrMfLMRBDdJukdMi7`)

```

  racketlab-seoulrave.vercel.app
  racketlab-git-main-seoulrave.vercel.app
```

- **커스텀 도메인이 하나도 연결되어 있지 않다.** 셋 다 `*.vercel.app` 서브도메인이다.
- 프로젝트 생성: 2026-04-08
- 최신 프로덕션 배포: 2026-08-12 (`READY`)

**귀결 — 개명 반대 논거의 핵심이 무너진다**

`vercel.app` 은 Public Suffix List 등재 도메인이다. 즉 각 서브도메인은
검색엔진에게 별개 사이트로 취급되며, 상위 도메인의 신뢰 자산을 물려받지도,
자기 자산을 크게 축적하지도 못한다.

따라서 **"개명하면 그동안 쌓은 SEO 자산을 잃는다"는 주장은 이 프로젝트에 해당하지 않는다.**
잃을 도메인 자산이 애초에 존재하지 않는다. 301 리디렉션 설계도, Search Console 주소 변경도
필요 없다. 백링크 갱신 대상도 사실상 없다.

**이것은 개명을 지지하는 방향의 사실이다.** 동시에 더 불편한 사실이기도 하다 —
서비스가 4개월간 운영되면서 아직 자기 도메인을 갖지 못했다. 이름을 정하는 일과
도메인을 붙이는 일은 어차피 함께 해야 하는 하나의 작업이다.

### 6.6 트래픽 측정 — **계측 장치 미설치 확인**

크리틱 세션과 아트 디렉터 세션이 각각 트래픽 데이터를 요구했다.
- 크리틱: "월간 유입과 검색 유입 비중은? (혼동 손실의 규모)"
- 아트 디렉터: "홈을 거치지 않는 세션이 다수일 것 [가정: 실측 데이터 없음.
  Vercel Analytics의 랜딩 페이지 분포로 즉시 검증 가능]"

**조회 결과** (Vercel Web Analytics API, 2026-04-08 ~ 2026-08-13 전 기간)

```
mode: count   → { visitors: 0, pageviews: 0 }
mode: aggregate by route → data: []
```

**0의 의미를 오독하면 안 된다.** 원인을 확인했다.

```
$ grep -n "analytics\|speed-insights" package.json
→ package.json 에 analytics 의존성 없음

$ grep -n "Analytics\|SpeedInsights" src/app/layout.tsx
→ layout.tsx 에 Analytics 컴포넌트 없음
```

`@vercel/analytics` 가 **설치되어 있지 않고**, 루트 레이아웃에 `<Analytics />` 가 없다.
따라서 `visitors: 0` 은 **"방문자가 없다"가 아니라 "측정된 적이 없다"** 를 뜻한다.

**귀결 — TF 논의의 절반이 측정 불가 위에 서 있었다**

프로젝트가 2026-04-08에 생성되어 2026-08-12까지 배포가 이어지는 동안,
**약 4개월간 아무것도 측정되지 않았다.** 그 결과:

- "리브랜딩하면 잃을 트래픽이 얼마인가" → 답할 수 없다
- "racketlab.app 과의 혼동으로 인한 실제 손실" → 답할 수 없다
- "사용자가 홈을 거치는가, 상세로 직행하는가" → 답할 수 없다
- "1순위 세그먼트와 2순위 세그먼트의 실제 비중" → 답할 수 없다
- "어떤 라켓이 실제로 조회되는가" → 답할 수 없다

네 세션 모두가 트래픽 가정 위에서 논증했고, 그 가정은 **검증 가능한 적이 없었다.**

**이것이 이번 TF에서 나온 가장 실행 가능한 발견이다.** 브랜드 결정보다 앞선다.
계측 없이 내리는 브랜드 결정은 전부 취향이다.

**미확인:** Vercel 대시보드에서 Web Analytics 기능 자체가 활성화되어 있는지는
API로 구분되지 않는다. 다만 클라이언트 스크립트가 없으므로 활성화 여부와 무관하게
데이터는 수집되지 않는다.

   실제로는 배경(`#0E1216`) 대비값이다. 표면 대비 실측은 **14.06**이다.
   둘 다 AAA를 넘으므로 결론은 바뀌지 않지만, 문서에 그대로 실으면 틀린 수치가 된다.
4. **오차 방향이 일정하지 않다.** 라이트는 대체로 과소(안전 방향)였으나
   다크 보조는 **과대**(7.06 주장 → 6.53 실측)였다. 즉 "보수적으로 계산했다"가 아니라
   그냥 부정확하다.
5. **N500(`#7C807C`)은 3.84로 큰글씨 AA(3.0)를 통과한다.** AD는 "UI 컴포넌트만" 이라고
   제한했는데, 18.66px Bold 이상 또는 24px 이상 텍스트에는 쓸 수 있다.
   다만 제한을 그대로 유지하는 편이 안전하다.

**결론: 팔레트는 채택 가능. 단, 모든 수치는 위 실측값으로 교체한다.**

## 6.8 아트 디렉터 3안 — 축소 생존 실측

AD 세션은 3안의 16px 생존을 **판정만** 하고 렌더로 확인하지 않았다.
규격대로 SVG를 작성해 **실제 px로 래스터화**한 뒤 12배 nearest 확대로 픽셀을 확인했다.
(`scratchpad/brand/symbols2.mjs` → `symbols2.png`)

| 안 | AD 판정 | **실측 결과** | 일치 여부 |
|---|---|---|---|
| A 배분 | ❌ 불가 | 형태는 남고 **정보가 죽는다** | 부분 일치 |
| B 베벨 | ⚠️ 원으로 수렴, 기준면 소실 | **수렴하지 않는다. 기준면도 남는다** | **불일치** |
| C 겹침 | ✅ 양호 | 양호. 단 **AD가 놓친 약점 있음** | 부분 일치 |

### A · 배분 — "불가능"보다 정확한 표현이 있다

32px에서는 획 5개가 선명하고, 24px에서도 구분된다.
**16px에서 획 5개는 여전히 세어진다.** 즉 "물리적으로 불가능"은 과장이다.

문제는 다른 데 있다. 16px에서 **길이 차이(68/40/84/28/56)가 회색 얼룩으로 뭉개진다.**
1번(68)과 5번(56), 3번(84)의 구분이 사라진다. 그런데 **길이 차이가 이 안의 개념 전부**다
— "5축은 서로 다른 값을 가진다"를 형태로 말하는 것이 A안의 유일한 논거다.

**정확한 판정: 그릴 수는 있으나 그려도 아무 말을 하지 못한다.**
AD의 결론(부적합)은 맞으나 근거는 틀렸다.

### B · 베벨 — AD의 판정이 틀렸다

AD는 이렇게 썼다:

> "정팔각형은 14px에서 **원으로 수렴한다.** 그 순간 '원 하나짜리 심볼'이라는
> 폐기 컨셉으로 되돌아간다. 이건 치명적이다. 16px 전용 그리드 스냅 버전
> (팔각 → 육각 근사)을 별도 제작하지 않으면 이 안은 파비콘에서 죽는다."

**실측은 다르다.**
- 16px에서도 윤곽이 **명확히 각져 있다.** 원으로 보이지 않는다.
- 우상단 45° 기준면(두께 2배 획)이 **16px에서도 식별된다.** 소실되지 않는다.
- 따라서 **16px 전용 별도 버전이 필요 없다.** 단일 마스터로 파비콘까지 커버된다.

이는 B안의 평가를 실질적으로 끌어올린다. AD가 B안의 최대 결함으로 지목한 것이
실재하지 않았고, "사실상 두 번째 로고를 만들어야 한다"는 비용 추정도 무효다.

**[주의]** 이 실측은 안티에일리어싱이 켜진 표준 래스터화 기준이다.
실제 브라우저·OS 파비콘 렌더러는 힌팅이 달라 결과가 다를 수 있다.
최종 확정 전 실제 브라우저 탭에서 확인이 필요하다.

### C · 겹침 — 살아남지만 AD가 놓친 약점

16px까지 두 사각형이 구분되고 어긋남도 유지된다. AD 판정대로 축약 없이 생존한다.

**그러나 AD가 언급하지 않은 문제가 있다.** 기본형의 두 번째 도형은 Ink 20% 농도인데,
흰 배경에서 **거의 보이지 않는다.** 32px에서도 옅고, 16px에서는 존재감이 사라진다.

AD는 "1색 3농도라 인쇄·자수·각인 전부 대응"을 C안의 강점으로 꼽았지만,
실제로는 **저대비 환경에서 3농도가 2농도로 붕괴**한다. 20%를 최소 35~40%로
올리거나, 두 번째 도형을 면이 아니라 윤곽선으로 바꾸는 수정이 필요하다.

### 종합

**AD의 우선순위 권고(C → B → A)를 그대로 받아들일 근거가 약해졌다.**
B안의 결정적 결함으로 지목된 것이 실재하지 않으므로, B와 C는 재평가 대상이다.
A안은 근거는 달라도 결론(부적합)이 유지된다.

### 「콘투리」 국내 검색 지형 — 직접 재확인

버벌 세션의 주장:
> "국내 웹문서 58건은 **전부** 이탈리아 돌로미티의 콘투리네스(Conturines) 산봉우리에

> 해외에서도 **정확 일치 기업이 확인되지 않았습니다.**"

**직접 조회한 결과 — 대체로 맞으나 한 가지가 빠졌다.**

총 58건. 확인된 내용:
- 호텔 **콘투리**네스 (야놀자), 돌로미티 산 카시아노 라이딩·트레킹 가이드(komoot ×2),
  조선일보 돌로미테 트레킹 기사 — **콘투리네스 부분 매칭이 다수인 것은 사실**
- 라틴어 위키낱말사전 `contuli`, 무관한 위키 문서 등 노이즈

**그러나 단독 용례가 존재한다.**
- **페피 콘투리(Peppi Konturi)** — 핀란드 여자 축구 라인업(HPS vs VIFK 바사)에 등장.
  **Konturi는 핀란드 성씨다.**

**판정:** "정확 일치 기업 없음"은 참이지만, **"정확 일치 없음"은 거짓**이다.
Konturi는 실존하는 핀란드 성씨이며, 확인된 단독 용례가 **축구 선수**라는 점에서
스포츠 인접 제약을 스친다.

**실무 영향은 작다** — 58건은 절대량이 미미하고, 성씨는 그 자체로 상표 장벽이 아니다.
다만 상표 검토 시 핀란드·EU 권역을 별도로 확인해야 하며,
"완전 백지"라고 서술하면 사실과 다르다.

## 6.10 「채 / CHAE」 방향 — 민호 제안 실측

### 개념적 정당성 — 확인됨

**나무위키 「라켓」 문서:** *"우리말로 그냥 **'채'**라고도 한다."*

- 채는 이 카테고리의 정당한 우리말 총칭이다. 설명이 필요 없는 이름이라는 점에서
  지금까지 검토한 모든 조어(콘투리·임팍툼·탁투스)보다 우위에 있다.
- **카테고리 확장성이 압도적이다.** 테니스채 · 배드민턴채 · 스쿼시채 · **골프채**.
  「라켓」은 골프를 담지 못한다. 마켓플레이스 확장 시 이름이 발목을 잡지 않는다.
- 「배드민턴채 스쿼시채」 네이버 웹문서 **58,668건** — 실사용되는 말이다.
- 조사 검사(D-2) 통과: 채가 / 채를 / 채에서.

### 그러나 세 개의 벽이 있다

**벽 1 — 테니스에서 「채」는 소수 표기다.**

**채는 골프의 단어다.** 골프채(71.3)는 테니스라켓(80.0)과 거의 대등한데,
테니스채(9.8)는 그 **약 8분의 1**이다. 한국 테니스인은 「라켓」이라고 부른다.

| racket-lab.app | 가용 | $9.99 |
| racket-lab.io | 가용 | $37.99 |
| racket-lab.co | 가용 | $4.99 |
| racket-lab.net | 가용 | $13.50 |

**핵심 발견: 하이픈을 넣어도 `.com`을 얻지 못하는데, 하이픈 없는 `.co`는 얻는다.**

`racketlab.co` $4.99가 가용하므로 **하이픈을 쓸 이유가 없다.**
하이픈은 크리틱이 지목한 비용만 남긴다 —
*"구두 전달이 불가능해진다('하이픈 있냐고요?'). 오프라인 매장 영업에 치명적."*
매장 입점이 로드맵에 있으므로 이 비용은 실재한다.

**권고: `racketlab.co` 단독. 필요하면 `racketlab.shop`을 커머스 전환용으로 병행.**

**미확인:** `.kr` · `.co.kr` — Vercel API가 취급하지 않는다.
국내 시장 우선이라면 `.co`보다 나을 수 있으므로 국내 등록대행에서 별도 확인이 필요하다.

### 유지 결정에 따라 남는 것 / 사라지는 것

**남는 리스크**
1. **동일 카테고리 서비스 충돌 지속** — `racketlab.app`은 지금 가동 중이며
   "detailed reviews, comparisons and expert guides" for tennis rackets를 내걸고 있다(직접 페치 확인).
   「라켓랩」 검색 트래픽 일부가 그쪽으로 간다.
2. **상표 확인 의무는 사라지지 않는다** — 오히려 더 중요해진다.
   상대가 먼저 등록했다면 사용중지 청구의 대상이 되는 쪽은 우리다.
   35류(판매중개) + 42류(플랫폼)를 **둘 다**. 판매 개시 전이 마지막 저비용 구간이다.

**사라지는 부담 — 그리고 그 시간이 어디로 가야 하는가**
- `brand.ts` 추출 · 표기 통일 · 스토리지 키 마이그레이션의 **긴급성이 사라진다.**
- 그 시간은 **R-1 계측 설치 · R-2 세그먼트 가드 · R-3 대비 수정**으로 가야 한다.
- 크리틱의 지적이 여기서 유효해진다 — *"이름을 바꾼다고 어필리에이트 링크가 등록되지는 않는다."*

**개명 여부와 무관하게 지금 해야 하는 것**

표기 통일. `racket LAB` 12회 / `racketlab` 5회 / `RacketLab` 2회.
이름을 유지한다면 **세 표기 중 무엇을 정본으로 삼을지** 먼저 정해야 한다.
이 결정은 오늘 할 수 있고, 도메인 결제보다 앞선다.

## 7. 이 문서가 확인하지 **않은** 것

아래는 확인하지 않았다. 결론에 사용하면 안 된다.

- 상표 등록 여부 (KIPRIS / USPTO / 마드리드) — 조회 수단 없음. 변리사 영역.
- `.kr` 도메인 가용성 — Vercel API가 취급하지 않음.
- `racketlab.app` 의 도메인 등록 시점 (WHOIS).
- 일본어·중국어권 발음 충돌 — 원어민 검증 미실시.
- 새 후보군의 도메인·충돌 — 후보가 확정된 뒤 이 문서에 추가한다.
