# Chapter 18 — 하단 탭바 자체 아이콘 시스템

### 목표
"하단 네비게이션 아이콘이 조악하다"는 민호의 지적. 조각(JOGAK) 앱 디자인을
참고해 라켓랩 고유의 아이콘 시스템을 만든다.

### 원인
아이콘이 아니라 **이모지 다섯 개**(🏠🔍🧵⇄♡)였다. 출신이 서로 다르고,
플랫폼마다 다르게 그려지고, `⇄`·`♡` 는 텍스트 글리프라 무게가 제각각이다.
한 줄에 세우면 조악해 보일 수밖에 없는 구성이었다.

### 조각에서 가져온 것과 안 가져온 것
`brand/BRAND-SPEC.md` §10 의 **아이콘 규율만** 가져왔다 — 24 그리드,
round cap, 몸통이 있는 글리프는 켜질 때 면으로 채움. 조각은 잉크 바 위의 흰
글리프라 stroke 2 로 눌러 그렸지만, 여기는 흰 바 위의 잉크 글리프이고
`.impeccable.md` 가 미니멀·프리미엄을 요구하므로 **1.75** 로 낮췄다.

조각의 다크 바·코럴 FAB 는 가져오지 않았다. `.impeccable.md` §5 가 Omega
시각 정체성 유지를 명시하고 있어, 나이트라이프 톤을 그대로 옮기면 어긋난다.

### 완료 내용
- `src/components/tab-icons.tsx` 신설. 다섯 글리프를 전부 라켓에서 뽑았다.
  색은 전부 `currentColor` 라 부모의 text 색이 켜짐/꺼짐을 정한다.
- 활성 표시는 바 윗선에 걸치는 **라임 실 한 가닥**(16×2px). 라임은 브랜드
  규칙대로 방향 지시에만 쓴다.
- **찾기 글리프는 한 번 다시 그렸다.** 처음엔 "빈 프레임(찾기) vs 채워진
  베드(스트링)" 로 갈랐는데, 96px 로 확대해 검수하니 23px 에서 stroke 1.75 가
  스로트 구멍(약 0.4px)을 메워 **막대사탕**으로 읽혔다. 작은 크기에서 라켓을
  라켓으로 만드는 건 스트링 베드다. 찾기를 베드까지 있는 온전한 라켓으로 두고
  스트링은 릴로 갈라 실루엣이 겹치지 않게 했다.

### 함께 고친 것 — 탭바를 손대면서 드러난 버그
- **`.safe-bottom` 이 정의되지 않은 죽은 클래스였다.** 두 곳에서 쓰이는데
  globals.css 에 규칙이 없어 아무 일도 하지 않았고, 아이폰에서 탭바와 진단
  하단 바가 홈 인디케이터에 깔렸다. 클래스를 정의하고 `env()` 가 0 이 아닌
  값을 주도록 `viewport-fit=cover` 를 켰다.
- **탭 활성 판정이 `pathname.startsWith(href)`** 라서 라켓 상세와
  커스터마이저에서 아무 탭도 켜지지 않았고 `/racketsXXX` 에는 반대로 켜졌다.
  경로 경계를 지키는 match 목록으로 바꿨다.
- 탭바 높이를 `--tab-bar-height` 로 묶어 비교 트레이가 인디케이터 높이까지
  포함해 비키게 했다. 안 그러면 노치 기기에서 겹친다.
- 링크에 focus-visible 링이 없었다. `.impeccable.md` 가 키보드 포커스를 요구한다.
- 검색 드롭다운의 🎾 도 같은 라켓 글리프로 교체했다.
- 찜 배지 `red-500` → 잉크. 팔레트에 없는 색이었다.

### 검증

### 남은 확인
- `viewport-fit=cover` 는 노치 아이폰 **가로 모드**에서 좌우 여백 동작이
  달라질 수 있다. 세로는 확인했고 가로는 실기기 확인이 필요하다.
